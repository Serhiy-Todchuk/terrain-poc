# Volumetric clouds (docs/weather_roadmap.md step 4, the cloud quality level
# "Volumetric"): the HRRR + GOES-19 layers ray marched as volumes with drifting
# 3D noise at half resolution, temporally filtered, composited over the scene
# with the per-sample depth test. The day case 2026-10-10 17:05 (cumulus under a
# high deck, GOES-19 scan 17:01) from the water, below, inside and above the low
# layer, 30 km (each layer alone, drift, fog, transparency, MSAA off, a smaller
# window), 700 km; the sun applied at sunset and at night; a flight (no wait:
# the temporal filter while moving); key 8 wraps around to Simple shell; an A/B
# of the frame time.
# Needs the network once (the GOES-19 scan of 22:11 for the sunset, ~9 MB; the
# other hours and scans are those of clouds_test / goes_test); then it replays
# with --offline.
# Run: TerrainPOC.exe --script ..\..\scripts\volumetric_test.txt --shot-dir ..\..\shots\volumetric --offline --no-vsync
# Expected log: "Cloud noise: 128^3 shape + 32^3 detail RGBA8 3D textures
# (9.3 MB with mips)" at start; "Settings panel: cloud quality Volumetric
# (--cloud-level volumetric)" after the combo click; the HUD line "layers ... |
# volumetric"; 0 errors, 0 warnings. A/B (RTX 3070 Laptop, 1600x900, 4x MSAA,
# --no-vsync, see the "stats" lines after each "A/B" note): Volumetric costs
# ~1.3-1.6 ms (from the water) and ~0.4-0.8 ms (30 km) more than Satellite
# observed (runs differ with the GPU clocks).
# Images: v* = 17:05 volumetric, s* = the same views at Satellite observed
# (slabs); the cover per layer agrees from 700 km, the volumes add billows,
# eroded edges and depth.
