# Cloud lighting (docs/weather_roadmap.md step 5, the cloud quality level
# "Volumetric + light"): the volumes of step 4 with the improvements of step 5,
# each switchable for an A/B of look and cost (panel rows under the Quality
# combo, keys 9 / 0, script "set sunmarch|multiscatter on|off"):
#   Sun march            - the optical depth towards the sun marched through the
#                          layer (self-shadowing) instead of the step-4 estimate
#   Multiple scattering  - orders of scattering + the deep diffuse light instead
#                          of the step-4 two-stream light
# Both off = the level "Volumetric". The views of volumetric_test (2026-10-10
# 17:05, cumulus under a high deck, GOES-19 scan 17:01; the sun applied at 17:05,
# at sunset 22:15 and at night 00:05). Images: v* = Volumetric, s* = sun march
# only, m* = multiple scattering only, l* = both (the level's default). A switch
# of level or improvement resets the temporal history (no blend of the two).
# All data is that of volumetric_test: run that once online, this one once
# online (terrain tiles of the new views), then it replays with --offline.
# Run: TerrainPOC.exe --script ..\..\scripts\lighting_test.txt --shot-dir ..\..\shots\lighting --offline --no-vsync
# Expected log: "script cloudlevel: cloud quality Volumetric + light (--cloud-level
# lit)"; "Settings panel: Sun march off" / "on" after the clicks; the HUD line
# "layers ... | volumetric + light (sun march, multiple scattering)"; 0 errors,
# 0 warnings. A/B (RTX 3070 Laptop, 1600x900, 4x MSAA, --no-vsync, the "stats"
# lines after each "A/B" note, in the order volumetric, sun march, multiple
# scattering, both, twice): both cost ~0.8 ms from the water and ~0.65 ms at
# 30 km more than Volumetric, nearly all of it the sun march; multiple
# scattering alone is within the noise (runs differ with the GPU clocks).

weather 202610101705
set panel off

# silver linings, darker cores
